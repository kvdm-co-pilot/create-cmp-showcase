This repository is not hand-written. Every commit below was produced by
[**create-cmp**](https://github.com/kvdm-co-pilot/create-cmp) — the AI delivery harness for

> **The harness, in one line:** the scaffold is the front door; the product is that an AI session
> *cannot* mark work done until a spec-cited, architecture-conformant change carries a committed
> evidence receipt that hashes to the exact tree it attests.

## What you are looking at

A stock Android + iOS Compose Multiplatform app, generated non-interactively, then extended by one

The receipt lives at [`qa/evidence/latest.json`](./qa/evidence/latest.json). CI
([`verify.yml`](./.github/workflows/verify.yml)) re-runs the lane on every push and, critically,
checks that the committed receipt's `inputs.hash` matches `HEAD` — a stale or hand-edited receipt
fails the build. That last row is the whole game: the `Favorites` files were *untracked* when the
lane ran, yet the receipt still hashes to the tree they were committed with.

## The eight gates

Every commit is held to all eight, on `:composeApp:desktopTest` plus an on-device Maestro smoke:

`specCoverage` · `build` · `unitTests` · `conformance` · `goldenTrees` · `tokenDrift` · `a11y` · `e2eSmoke`

- **specCoverage** — every `specs/*.spec.md` clause is cited by a test, and every test tag traces
  back to a clause. Orphan behavior or orphan citations fail the lane.
- **conformance** — dependency-free architecture gates enforce the Clean-Architecture layer
  boundaries. Reach across a layer and the lane names the violated clause.
- **tokenDrift** — the live debug inspector (`127.0.0.1:9500`) is queried and the rendered design
  tokens are compared against the declared catalog. Hardcode a color and it drifts.
- **e2eSmoke** — a real Maestro run on an emulator, hardened for cold-start and slow CI.

## See it refuse

The harness earns trust by *refusing*, not by passing.
[**PR #1**](https://github.com/kvdm-co-pilot/create-cmp-showcase/pull/1) injects a single hardcoded
color and is blocked at **two independent layers** — that reinforcement is the point:

1. **The receipt gate** (CI's first step + the local Stop hook, both `qa/receipt-check.mjs`): the
   change carries no valid `PASS` receipt for its tree, so it's refused *before a single test runs*.
   And you can't manufacture one — producing a `PASS` receipt requires the lane to pass, and it won't.
2. **The conformance lane** (`node qa/verify.mjs`): names the exact clause by hand —
   `ARCH-05 no hardcoded Color literals outside the theme FAILED`. Not "a test broke": *this rule,
   in this file.*

A green checkmark is cheap; a red one that cites the rule — and a receipt you cannot forge — is the
product.

## Run it yourself

```bash
# Android (device/emulator attached)
./gradlew :composeApp:installDebug

# Desktop dev-client with Compose Hot Reload — the daily dev loop
./gradlew :composeApp:hotRunDesktop --auto

# The full verify lane, exactly as CI runs it
node qa/verify.mjs --profile local

# Prove the receipt matches the tree (what CI enforces)
node qa/receipt-check.mjs
```

**iOS:** `cd iosApp && xcodegen generate && pod install`, then open `iosApp.xcworkspace` in Xcode.
